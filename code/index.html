What it does

A loop, real tools, and a transcript you can audit.

Context → stream → tool calls → results → repeat, until the model is done, you stop it, or the iteration limit is hit.

FIG. 01

Fifteen real tools

read_file, write_file, edit_file, search_files, run_command, git_commit and the rest. Every write returns a unified diff instead of claiming success.

FIG. 02

Approval where it matters

Destructive steps pause and ask. A hard blocklist refuses disk formatting, root deletes, privilege escalation, git push, reset --hard and pipe-to-shell downloads outright.

FIG. 03

Two tool protocols

Native function calling for OpenAI-compatible endpoints, plus a text <tool_call> protocol for local models that never learned tool calling.

FIG. 04

A real shell

xterm.js wired to a child process: streaming stdout and stderr, exit codes, history, cd tracking, Ctrl+C and process-tree kill.

FIG. 05

Project context

Ignore-aware scanning, language and framework detection, entry-point scoring, grep and filename search — with .env* excluded, not slurped.

FIG. 06

Sessions that survive

One JSON file per session, written atomically, with an index, rename, delete, clear and recovery after a crash.

Three modes

It changes behaviour, not just the label.

The mode chip in the composer decides what the agent is allowed to do on the next run.

PLAN

Read-only by construction

Write, move and delete tools are withheld and refused at execution time. The agent publishes steps with update_plan and stops — approve to start the real run, or edit the plan first.

BUILD

The default

Inspect, change, verify, report in one run. Writes still show diffs; risky commands still ask.

MISSION

Unattended, with a gate

A multi-stage objective with a tripled iteration budget, safe commands auto-approved — but commits stop at a review gate that shows the actual git diff.

FAQ

Before you point it at a repo.

Does it need an API key to start?

No. Pollinations is seeded and keyless, and Ollama or LM Studio need no account at all. Keys are only for the free hosted tiers and the paid APIs, and they are stored with the OS keychain (DPAPI on Windows).

Can it push, reset or delete things on its own?

It never pushes. git push, git reset --hard, disk formatting, recursive deletes of roots, privilege escalation and pipe-to-shell downloads are refused by a hard blocklist. Deletes and moves stop for approval, and mission mode's commit path shows the diff first.

What are the real limitations?

The shell is line-oriented — full-screen TUIs such as vim or htop are not supported, which is stated in Settings → Terminal. There is no extension marketplace, no multi-window project tabs, and storage is JSON rather than SQLite.

Does the smoke suite use a real model?

It runs the whole agent loop against a mock OpenAI-compatible server: streaming, native tool calls, tool execution, confirmations and cancellation. That is how it verifies behaviour without a key or a bill.

Can I import my existing chats?

Yes — Sessions → import chats reads the Freebuff/Codebuff desktop client's desktop-v2.db stores and turns every thread into a session. Re-running skips threads that already exist.
